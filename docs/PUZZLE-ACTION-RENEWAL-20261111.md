## 1. 지금 상태와 바꿀 점

지금 게임은 5구역 10활동이고, 활동마다 큰 실험대에서 자석을 직접 끌고 뒤집는다. 조작은 이미 있지만 흐름이 「실험 → 관찰 → 결과 확인 → 도시 복구」라서 학생에게는 '시키는 실험을 차례로 하는 것'으로 느껴진다. 부족한 것은 네 가지다.

| 부족한 것 | 지금 | 바꾼 뒤 |
|---|---|---|
| 해야 할 이유 | 활동 제목과 안내 문장 | 구역마다 눈에 보이는 위기 한 장면 |
| 막는 것 | 없음. 순서대로 하면 끝남 | 자석의 성질을 써야만 치워지는 장애물 |
| 틀렸을 때 | 안내 문구가 바뀜 | 물체가 실제로 다르게 움직이고 그 자리에서 다시 함 |
| 풀었을 때 | 다음 버튼 → 발견 정리 → 보상 화면 | 푸는 순간 장애물이 치워지고 시설이 살아남 |

목표 흐름은 **위기 발생 → 자석 조작 → 퍼즐 해결 → 즉각 보상 → 다음 구역 해금**이다.

## 2. 핵심 규칙: 도구는 자석 하나, 조작은 세 가지

학생이 쥐는 것은 자석 하나다. 모든 퍼즐은 아래 세 조작만으로 풀리고, 장애물은 과학 규칙대로만 반응한다. 버튼을 눌러 답을 고르는 퍼즐은 만들지 않는다.

| 조작 | 쓰이는 자석의 성질 | 성취기준 |
|---|---|---|
| 가까이 대기 · 멀리 떼기 | 철로 된 물체만 끌려온다. 가까울수록 세고, 떨어져 있어도 작용한다 | 4과09-01 |
| 사이에 두고 움직이기 | 종이·유리가 사이에 있어도 힘이 작용한다 | 4과09-01 |
| 뒤집기 | 같은 극은 밀어내고 다른 극은 끌어당긴다 | 4과09-02 |

난이도는 조작을 복잡하게 해서 올리지 않는다. **어떤 성질을 쓸지 판단하게** 해서 올린다. 한 화면의 조작 수는 지금보다 늘리지 않는다.

## 3. 구역별 퍼즐

기존 10활동의 자리(저장 칸 1~10)와 그림·소품·캐릭터·주민 음성을 그대로 쓴다. 각 활동을 '위기를 푸는 퍼즐'로 다시 짠다. 악당은 이미 지도에 있는 고철 도깨비를 쓴다.

| 구역 | 위기 | 퍼즐 A | 퍼즐 B | 오늘 알게 된 것 |
|---|---|---|---|---|
| 1 생활 자석 조사국 | 도깨비가 걸쇠 자석을 빼 가서 우편함이 열리고 편지가 날린다 | 우편함 조립(기존, 짧게) | 바람이 불기 전에 자석을 철판 맞은편에 끼워 덮개 잠그기. 나무 쪽이나 먼 자리에 끼우면 덮개가 열려 편지가 날아가고, 그 자리에서 다시 한다 | 자석은 철에 붙어서 덮개를 닫아 준다 |
| 2 힘 실험 연구소 | 고철 더미가 쏟아져 기계와 길이 막혔다 | 자석 크레인으로 철 부품만 건져 길 열기. 알루미늄·나무는 따라오지 않아 손으로 치운다 | 틈 너머 철 열쇠 꺼내기. 멀면 안 움직이고, 가까이 가면 끌려오고, 종이 막이 있어도 끌려온다 | 철로 된 물체만 붙고, 떨어져 있어도 종이 너머에서도 끌려온다 |
| 3 극성 복원 센터 | 극 표시가 지워져 자석 문이 잠기고 승강 고리가 내려앉았다 | 기준 자석을 대 보고 문의 극을 알아낸 뒤, 맞는 극으로 당겨 여는 문과 밀어 여는 문 통과 | 고리자석을 뒤집어 띄워 발판을 올리고, 다시 붙여 내려서 밀이·당이를 건네기 | 같은 극은 밀어내고 다른 극은 끌어당긴다 |
| 4 원격 제어 구역 | 수조가 이끼로 덮이고 택배 레일이 멈췄다 | 유리 밖 손잡이로 안쪽 패드를 끌어 이끼 닦기. 너무 빨리 떼면 연결이 끊겨 다시 붙여야 한다 | 택배 카트를 밀고 당겨 깃발에 세우기. 구간이 늘며 중간 정차와 반대 방향 운반이 나온다 | 자석은 유리 너머 물체도 움직이고, 밀기와 당기기로 보내고 세울 수 있다 |
| 5 시민 발명 공방 | 주민의 불편 의뢰가 쌓였다 | 발명 설계(기존 유지) | 내 발명품 사용 시험(기존 유지) | 자석의 성질을 골라 쓰면 생활의 불편을 고칠 수 있다 |
| 광장 | 도깨비 대장이 도시 중심 장치를 잠갔다 | 네 성질을 차례로 쓰는 짧은 연결 퍼즐(붙이기 → 거리 → 극 → 유리 너머). 끝나면 지금의 수첩 정리와 엔딩으로 이어진다 | | |

5구역은 성취기준 4과09-03이 '설계하고 고치기'라서 퍼즐로 바꾸지 않는다. 대신 앞 네 구역에서 익힌 조작을 광장 연결 퍼즐에서 한 번 더 쓴다.

## 4. 한 판의 구성

1. **위기 장면** 10초 안쪽. 기존 삽화·도깨비 스프라이트·주민 음성으로 만들고 건너뛸 수 있다. 고르는 단계 없이 바로 퍼즐로 넘어간다.
2. **퍼즐**. 화면 위에 목표 한 줄과 단계 점(● ● ○)만 둔다. 처음 잡을 물체는 움직이는 강조와 손가락 표시로 알려 준다.
3. **틀렸을 때**. 벌점이 없다. 편지가 날아가거나 카트가 지나치는 식으로 결과가 눈에 보이고 그 자리에서 다시 한다. 두 번 막히면 '어디를 볼지', 세 번 막히면 '무엇을 비교할지'를 알려 주고, 그래도 막히면 지금 있는 자동재생을 권한다.
4. **풀었을 때**. 그 순간 장애물이 치워지고 도깨비가 물러나며 시설 그림이 복구된 모습으로 바뀐다. 효과음과 별이 함께 나온다.
5. **구역 마무리**. '오늘 알게 된 것' 한 문장을 학생이 고르거나 확인하고(지금의 발견 정리를 한 장으로 줄인다), 도구를 받고, 지도에서 다음 구역 길이 열린다.

별은 세 개다. 직접 풀면 하나, 힌트 없이 풀면 하나, 한 번에 풀면 하나다. 시간은 재지 않는다. 느린 학생에게 불리하고 수업 중 경쟁을 만든다.

## 5. 지키는 것

- 실험·캐릭터·지도·에셋·주민 대화·개념 영상·연구 가방·광장 수첩·인증서·엔딩은 그대로 둔다.
- 자석의 반응은 지금의 과학 모형(`domain.ts`, `mission-model.ts`)을 그대로 쓴다. 재미를 위해 사실과 다른 움직임을 만들지 않는다. N극·S극 표기, 알루미늄이 붙지 않는 것, 거리와 종이 조건을 유지한다.
- 이미 저장된 진행·증거·인증서는 그대로 유효하다. 저장 구조의 버전은 올리지 않고 값만 더한다. 진행 중이던 활동은 기존 규칙으로 끝낼 수 있고, 새로 시작하는 활동부터 퍼즐 규칙을 쓴다.
- 드래그가 어려운 학생을 위한 '눌러서 이동'과 키보드 조작, 자동재생, 교사용 전체 해금을 유지한다.
- 새 의존성은 넣지 않는다. 지금의 실험대(`Surface`)를 그대로 쓰고 별도 게임 엔진을 들이지 않는다.

## 6. 만드는 방법

- 퍼즐 규칙(무엇이 되면 풀린 것인지, 별 계산)은 `mission-model.ts`에 순수 함수로 더하고 테스트를 먼저 쓴다.
- 구역별 장애물은 지금의 `missions-*.ts` 안에서 라운드를 퍼즐 단계로 바꾼다. 파일을 새로 나누지 않는다.
- 새로 만드는 파일은 둘이다. 위기 장면(`crisis.ts`)과 퍼즐 머리띠·별·다시 하기(`puzzle-hud.ts`). 둘 다 DOM으로 만든다.
- 지도의 도깨비는 지금 '탐구 뒤 세 번 누르기'인데, 퍼즐을 푼 순간 물러나는 연출로 잇는다.

## 7. 순서

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1 | 한 구역을 끝까지: 4구역 택배(활동 8)를 위기 장면 → 장애물 코스 → 별 → 시설 복구 → 지도 해금까지 완성 | 1024×768·1280×800·1920×1080에서 처음부터 끝까지 직접 조작해 통과 |
| 2 | 위기 장면·퍼즐 머리띠·보상 흐름을 다섯 구역에 적용 | 기존 저장으로 이어하기가 깨지지 않음 |
| 3 | 1 → 2 → 3구역 퍼즐 장애물 | 구역마다 틀린 조작이 눈에 보이는 결과로 나옴 |
| 4 | 4구역 수조, 광장 연결 퍼즐, 지도 해금 연출 | 처음부터 인증서까지 완주 |
| 5 | 최종 점검 | 아래 검증 전부 통과 |

택배를 먼저 하는 까닭은 이미 밀기·당기기·정차가 물리로 돌아가고 있어서, 가장 적은 변경으로 새 흐름 전체를 확인할 수 있기 때문이다.

## 8. 검증

단계마다 `npm test`, `npm run build`, `npm run test:browser`(10활동·최종 복구·3해상도)를 돌린다. 화면이 바뀐 단계는 `scripts/layout-audit.cjs`와 `scripts/tablet-layout-regression.cjs`를 더 돌리고 직접 조작해 확인한다. 마지막에 `edu-final-check`로 판정을 받는다.

확인하지 못하는 것은 미리 적어 둔다. 실제 학생의 재미·이해도·소요 시간, 학교 태블릿과 전자칠판의 손가락 조작감은 이 작업 안에서 잴 수 없다. 활동 목표의 교사 검수(`needsReview`)도 그대로 남는다.

## 9. 하지 않는 것

시간 제한, 순위표, 목숨, 로그인, 새 캐릭터 생성, 새 3D 모델, 배경음 교체. 운영 배포와 푸시는 따로 말이 있을 때만 한다.

## 10. 진행 기록

### 1단계 · 4구역 택배 「유리벽 보관실」 (2026-11-11)

- 코스: 조종 자석은 유리벽(가로 52)을 넘지 못하고 47.5에서 멈춘다. 깃발은 벽 너머 60에 있다. 당기기만 하면 카트가 벽 앞 41.5에서 멈추고, 자석을 뒤집어 뒤에서 같은 극으로 밀어야 들어간다. 계속 밀면 깃발을 지나치고(최대 65.5), 다른 극으로 당겨 되돌릴 수 있다. 과학 모형의 힘·마찰 식은 바꾸지 않았다.
- 빗나감: 벽에 막힌 당기기 한 번, 깃발을 지나쳐 멈출 때마다 한 번. 두 번째부터 단서가 한 단계씩 붙고 네 번째에는 자동재생을 권한다.
- 별: 저장하지 않고 배달 기록에서 계산한다(`puzzleStars`). 직접 풀면 3개에서 빗나감 한 번마다 하나씩, 최소 1개. 자동재생으로 풀면 0개이고 활동 완료는 인정한다.
- 위기 카드와 별 표시는 `src/puzzle-hud.ts`. 풀면 보관실 색이 바뀌고 도깨비가 달아난다. 보상 창에 같은 별이 나온다.
- 호환: 새로 시작한 택배 활동만 `puzzleVersion: 1`이 붙는다. 진행 중이던 활동과 광장의 옛 배송은 그대로다. 완료 판정 키(`segment0`, `delivery0`)는 같다.
- 검증: 단위 시험 269개(퍼즐 5개 추가), `npm run build`, 브라우저 회귀 21개 통과. 1280×800에서 실제 드래그로 벽 막힘 → 뒤집어 밀기 → 떼기 → 별 2개를 확인했고, 자동재생이 코스를 끝까지 푸는 것을 확인했다. 위기 카드는 1280×800·915×412, 실험대는 1024×768·915×412 화면을 캡처해 봤다.
- 확인하지 못한 것: 보상 창의 별 표시(회귀는 그 창을 지나가지만 별을 검사하지 않는다), 단서가 붙은 안내 문구의 실제 화면, 1920×1080 직접 조작, 실제 태블릿 손가락 조작.
- 남긴 것: 지도의 도깨비 세 번 누르기는 그대로 두었다. 915×412에서 '유리벽'·'배달 장소' 이름표가 안내 말풍선에 가려진다('배달 장소'는 이전부터 같다).

### 2단계 · 1구역 덮개 퍼즐과 활동 2~8 공통 틀 (2026-11-11)

- 1구역 활동 2 「어긋난 철판」: 도깨비가 자석을 빼 가면서 철판도 떨어뜨려 놓았다. 먼저 지금 상태로 흔들어 덮개가 열리는 것을 보고, 자석을 끼워도 철판이 멀면 다시 열리는 것을 본 뒤, 철판을 자석 맞은편으로 옮겨야 닫힌다. 예전 3라운드에 있던 철판 장치를 고르기 버튼 없이 직접 옮기는 퍼즐로 되살렸다. 철판이 어긋난 것을 먼저 알아채고 고치면 별 셋이다.
- 공통 틀: 활동 2~8을 새로 시작하면 위기 카드가 뜨고 별이 붙는다. 빗나감은 활동마다 이미 있던 '다르게 움직인 결과'에 연결했다(3 잘못된 분류함, 4 클립이 안 움직인 칸, 5 맞지 않는 극 스티커, 6 뜨지·붙지 않은 고리 배치, 7 패드가 떨어짐). 빗나감·단서 처리는 `Surface.miss`, 활동별 마지막 증거는 `mission-model.ts`의 `puzzleProof`에 있다.
- 설계표와 다른 점: 2·3구역과 수조에는 새 장애물을 만들지 않았다. 지금은 기존 실험에 위기·빗나감·단서·별만 입힌 상태다. 설계표의 '틈 너머 열쇠', '당겨 여는 문·밀어 여는 문', '고리 승강 발판'은 아직 없다. 활동 1(조립)과 5구역은 그대로다.
- 검증: 단위 시험 273개, `npm run build`, 브라우저 회귀 21개(활동 2는 자석만으로 열림 → 철판 맞춤 → 닫힘 경로), 태블릿 배치 회귀 205화면 0건 통과. 활동 2는 1024×768에서 실제 드래그로 첫 흔들기와 자석 끼운 뒤 열림까지 확인했고, 철판을 옮겨 푸는 단계와 두 번째 빗나감의 단서 문구는 헤드리스 크롬 캡처(`test-results/puzzle-20261111/`)로 확인했다. 활동 3~7은 위기 카드와 실험대 캡처만 봤다.
- 확인하지 못한 것: 활동 3~7의 빗나감 연결은 시험이나 조작으로 밟아 보지 않았다(회귀는 맞는 길만 간다). 활동 2 자동재생의 철판 옮기기, 보상 창의 별 표시, 1920×1080과 실제 태블릿 조작도 그대로 남아 있다. `scripts/autoplay-progress-regression.cjs`는 완주 저장 표본(TEST_FIXTURE)이 없어 돌리지 못했다.

### 3단계 일부 · 3구역 활동 5 「같은 극으로 여는 문」 (2026-11-11)

- 흐름: 기존대로 두 극을 대 보고 극 스티커를 붙여 표시를 되찾으면, 두 자석이 처음 자리로 돌아가고 그 자석이 문의 빗장이 된다. 빗장을 오른쪽으로 밀어내야 문이 열린다. 다른 극을 대면 빗장이 당겨져 문은 그대로이고(빗나감), 기준 자석을 뒤집어 같은 극을 대면 밀려나 열린다. 스티커를 보고 먼저 뒤집으면 별 셋이다.
- 완료 판정: 퍼즐로 시작한 활동 5는 기존 조건(두 반응 + 양쪽 스티커)에 문 열기 증거 `door0`이 더 있어야 끝난다. 진행 중이던 활동은 기존 조건 그대로다.
- 문은 캔버스로 그렸다. `magnetic-gate.webp`는 가장자리에 얼룩 픽셀이 있어 쓰지 않았다. 도깨비 퇴장 연출은 자리가 없어 넣지 않았다.
- 설계표와 다른 점: '당겨 여는 문'은 만들지 않고 '밀어 여는 문' 하나만 있다. 활동 6 '고리 승강 발판'과 2구역 '틈 너머 열쇠'는 아직 없다.
- 검증: 단위 시험 277개(문 시험 4개 추가), `npm run build`, 브라우저 회귀 21개(활동 5는 다른 극으로 빗나감 → 뒤집어 열기 경로), 태블릿 배치 회귀 205화면 0건 통과. 헤드리스 크롬 캡처로 잠긴 문·당겨진 빗장·열린 문 화면과 안내 문구를 확인했고, 자동재생이 스티커를 붙인 뒤의 문을 여는 것(별 0개, 자동 관찰 기록)을 확인했다.
- 확인하지 못한 것: 실제 드래그 조작(브라우저 창이 가려져 눌러서 놓기 방식으로만 확인), 1024×768 이하 화면에서 문과 다른 요소의 겹침을 눈으로 보는 것, 실제 태블릿 조작.
