## 실패 기록과 보정

- 탐구 증거 검사 첫 실행의 `oldSave`는 새로운 질문 정보가 든 표본을 이전 저장으로 사용해 실패했다. 11월 6일 이전 저장 표본으로 다시 실행해 통과했다.
- 같은 검사의 `regressions`는 새 위기 카드가 클릭을 가로막았다. 공통 진입 함수에서 출동하기를 누르도록 보정한 뒤 관련 회귀 7개가 통과했다.
- 첫 오프라인 검사는 서비스 워커 설치 전에 네트워크를 끊어 실패했다. 설치·제어 완료를 기다리고 오프라인 성공을 명시적으로 검사하도록 고친 뒤 통과했다.
- 택배 이름표 검사에서 CSS의 직계 자식 선택자가 실제 DOM과 맞지 않아 915×412가 실패했다. 자손 선택자로 수정하고 최종 화면을 다시 캡처했다.
- 추가 최종 재실행은 빌드 중 서버 응답 실패와 개발 서버 종료로 중단됐다. 이후 아래 저장 경로 문제를 발견해 전체 브라우저 재실행을 보류했다. 실패·중단 로그를 성공 결과에 합산하지 않았다.

## 저장 위치 확인과 브라우저 제약

작업 드라이브 `/Volumes/T7 Shield`는 USB 외장 ExFAT 볼륨으로 확인했다. 코드, 의존성, 빌드, 검사 결과와 지정한 임시·캐시 경로는 이 SSD에 있다.

브라우저 프로필을 외장 임시폴더에 만들었지만, 크롬의 Crashpad 프로세스가 `/Users/yel/Library/Application Support/Google/Chrome/Crashpad`와 같은 위치의 metrics 경로를 사용하는 것을 뒤늦게 확인했다. 실제 내장 쓰기량은 측정하지 못했다. 해당 경로를 발견한 뒤 진행 중인 검사 브라우저를 종료했다.

Crashpad 데이터베이스를 외장으로 지정하는 시험에서도 metrics 경로가 내장에 남았다. 외장 외 파일 쓰기를 차단하는 래퍼는 소켓 디렉터리를 만들지 못해 종료됐다. 따라서 크롬까지 포함한 전체 외장 저장은 완료 상태가 아니다. 기존 내장 데이터의 이동·삭제는 수행하지 않았다. 추가 브라우저 실행에는 외장 저장 구성 해결 또는 정확한 내장 경로에 대한 사용자 승인이 필요하다.
