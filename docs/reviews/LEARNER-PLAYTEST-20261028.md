# 직접 조작 플레이 점검 · 2026-10-28

## 확인 방법

로컬 앱을 1024×768 인앱 브라우저에서 열고, 화면의 안내를 읽으며 활동 1~10, 광장 복구, 인증서까지 직접 조작했다. 클릭과 드래그를 사용했으며 학습 상태를 바꾸거나 조작 이벤트를 주입해서 단계를 넘기지 않았다. 활동 3에서 물체가 겹쳐 막힌 상황은 화면에 제공된 실제 키보드 방향키 조작으로 벗어났다.

초등학생이 참여한 사용성 시험은 아니다. 태블릿 크기의 데스크톱 브라우저 점검이며 실제 iPad·Android 태블릿에서의 손가락 조작 검증과도 구분한다.

## 플레이에서 찾은 문제와 개선

| 구간 | 직접 조작 중 발견한 문제 | 개선 내용 |
|---|---|---|
| 공통 조작 | 물체 그림의 끝을 잡으면 이동이 시작되지 않아 다시 잡게 됨 | 그림 전체에 맞게 잡기 영역 확대 |
| 덮개·종이 | 덮개의 손잡이와 얇은 종이에서 어디를 잡아야 하는지 모호함 | 잡을 위치를 분명하게 표시 |
| 활동 3 재료 분류 | 선택 재료인 철못이 이동 중 붙고 물체가 겹쳐 자석을 다시 잡기 어려움 | 핵심 세 재료를 기본으로 제시하고 나머지는 더보기로 분리. 겹침을 풀 수 있게 하고, 붙지 않는 재료는 손으로 분류하도록 안내 |
| 활동 5 극 추론 | 기준 자석을 뒤집으면 처음 위치로 돌아가 같은 접근 조작을 반복 | 제자리에서 뒤집어 반대 극의 반응을 바로 관찰. 극 스티커를 원형으로 정리 |
| 활동 7 청소 | 얼룩 가운데 멈추면 진행이 덜 된 채 남아 추가로 얼마나 움직여야 하는지 모호함 | 패드를 실제로 한 번 쓸어 닦는 동작으로 진행하도록 조정. 가만히 두기만 해서는 청소되지 않음 |
| 활동 8 배송 | 성공 중에도 이전 오류 안내가 남고 조종 위치·연결 상태가 불분명함 | 상태에 맞게 안내 갱신, 조종점과 연결선 표시, 도착 구간 감속 |
| 코칭 | 이미 한 조작을 다시 안내하거나 다음 조작 대상이 분명하지 않음 | 현재 상태에 따라 다음에 잡거나 누를 대상을 안내 |
| 마지막 복구 | 활동 10에서 성공한 설계로 광장에서 같은 시험을 다시 수행 | 검증된 현재 설계는 실제 시험 증거를 보존한 채 장착으로 복구. 설계가 바뀌었거나 증거가 없으면 재시험 |

공통으로 필요한 개념 비교는 유지하면서, 같은 사실을 확인하기 위한 반복 이동과 불필요한 재시도를 줄이는 데 집중했다.

## 마지막 복구의 완료 조건

광장에 설치할 때 활동 10이 완료되어 있고, 새 활동 흐름의 실제 사용 성공 증거가 현재 설계 종류·버전과 일치하는 경우에만 그 증거를 복사해 사용한다. 설치만 했다는 이유로 시험 기록을 새로 만들어 성공시키지 않는다. 설계를 수정했거나 일치하는 성공 증거가 없으면 기존 사용 시험을 수행해야 한다.

이 변경은 [앞선 학습 흐름 개선 기록](LEARNING-FLOW-20261028.md) 이후의 후속 개선이다. 직접 전체 플레이에서 발견한 광장 재시험의 중복을 제거했으며, 이 마지막 변경까지 포함한 최종 회귀 결과는 아래 검증 기록과 구분해 확인한다.

## 직접 플레이와 자동 검증의 구분

| 구분 | 확인한 내용·상태 |
|---|---|
| 직접 UI 플레이 | 1024×768 화면에서 활동 1~10, 광장, 인증서까지 실제 입력으로 진행. 조작이 막히는 지점·안내 불일치·반복 피로 확인 |
| 개선 후 직접 재조작 | 활동 3: 자석 그림 끝 잡기·철 클립 운반·알루미늄/나무 손 분류까지 키보드 탈출 없이 완료. 활동 5: 한 번 접근 후 제자리 뒤집기·양극 스티커로 완료. 활동 7: 왕복 없이 세 얼룩을 이어 닦아 완료. 활동 8: 조종 자리와 정상 안내 전환 확인 |
| 단위 테스트·빌드 | 10개 파일, 141개 테스트 통과. TypeScript 검사 통과. 시스템 메모리 부족으로 일반 빌드 중단 후 `node --max-old-space-size=512 --max-semi-space-size=4 node_modules/vite/bin/vite.js build` 통과. 기존 3D 지연 로딩 청크의 크기 경고는 유지 |
| 자동 브라우저 회귀 | `scripts/playful-regression.cjs` 최종 19개 확인 항목 통과, 실행 오류·HTTP 오류 없음. 10개 활동, 최종 설치·인증서·재열기, 두 발명 종류, 실패 후 설계 수정, 원본 탐구 기록 보존을 확인. 1280×800·1024×768·768×1024에서 실제 터치 탭 배치 확인. 전체 활동의 자동 진행은 배치 이벤트를 사용하므로 직접 드래그 플레이와 구분. 결과·캡처: `test-results/playful-20261028/` |
| 실제 학생·실물 기기 | 미실시. 학생의 이해도·흥미·소요 시간과 실물 태블릿 입력감을 검증했다고 주장하지 않음 |

이번 변경은 로컬 개선이며 운영 배포는 하지 않았다.
