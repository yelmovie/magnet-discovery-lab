# PRP · 시민 발명 공방을 "아이디어 발표회"로 바꾸기

상태: 1~5단계 구현 완료(2026-11-04). 6단계 방 코드 학급 전시관은 미착수.

구현 중 바꾼 점: `Save.version`은 올리지 않았다. `idea`는 선택 필드라 이전 코드로 되돌려도 저장이 깨지지 않는다. 마지막 복구는 이미 정리 문제 방식이라 `invention` 경로를 바꾸지 않고, 수첩의 다섯째 기록에 발명 카드를 보여 준다.

## 1. 왜 바꾸나

지금 공방(활동 9·10)은 우편함 또는 원격 운반 도구 중 하나를 골라 자석과 대상 부품을 놓고 시험한다. 우편함은 활동 1·2, 원격 운반은 활동 7·8에서 이미 했다. 앞 구역은 "정해진 장치를 고치는" 활동인데, 마지막 구역까지 같은 구조라서 반복으로 느껴진다.

바꾼 뒤의 학생 목표는 한 문장이다.

> 나는 자석의 성질을 써서 누군가의 불편을 해결할 내 발명 아이디어를 만들고, 친구들에게 내 목소리로 소개한다.

앞 네 구역은 정답이 있는 탐구, 공방은 정답이 없는 창작으로 역할을 나눈다. 대응 성취기준은 기존 문서의 [4과09-03]이며, 원문은 구현 전에 다시 대조한다.

## 2. 학생 흐름 (활동 2개, 합계 약 30분)

### 활동 9 · 아이디어 공방 (약 15분)

1. **불편 찾기.** 의뢰 게시판에서 시민의 불편 하나를 고른다. 앞 구역에서 쓰지 않은 소재만 쓴다(칠판 지우개가 자꾸 떨어짐, 흩어진 압정 줍기, 손이 불편한 할머니의 가방 잠금 등). "내가 찾은 불편"으로 직접 써도 된다.
2. **자석 성질 고르기.** 앞 구역에서 얻은 발견 카드 다섯 장 중 쓸 성질을 고른다: 철을 끌어당긴다 / 다른 극은 당긴다 / 같은 극은 밀어낸다 / 얇은 물체 너머로도 힘이 미친다 / 멀어지면 힘이 약해진다.
3. **설계 스케치.** 손가락으로 그리고, 부품 스티커(막대자석, 고리자석, 철판, 끈, 바퀴, 경첩, 상자)를 붙이고, 힘 화살표를 그린다. 자석의 극을 표시한다.
4. **원리 점검.** 밀이·당이가 스케치를 보고 질문한다. "철 부품이 어디 있어?", "마주 보는 극은 뭐야?". 고른 성질과 놓은 부품이 맞는지 순수 함수로 판정하고, 틀려도 탈락시키지 않고 고칠 곳만 짚는다.

### 활동 10 · 발표회 (약 15분)

5. **이름 짓고 내 목소리로 소개하기.** 말하기 틀 세 개를 보며 최대 30초 녹음한다: 누구의 어떤 불편인지 / 자석을 어떻게 쓰는지 / 왜 그렇게 되는지. 다시 듣고, 마음에 안 들면 다시 녹음한다. 마이크를 못 쓰면 글로 쓴다.
6. **전시하기.** 발명 카드(스케치, 이름, 성질, 소개)가 공방 전시관에 걸린다.
7. **친구 의견 받기.** 친구가 스티커 하나(쓸모 있어 / 기발해 / 궁금해)와 질문 한 줄을 남긴다. 평가 점수와 순위는 없다.
8. **고치기.** 받은 의견 중 하나를 골라 스케치를 고치고 "바뀐 점" 한 줄을 쓴다. 이 기록이 활동의 완료 조건이자 발명 증거가 된다.

## 3. 공유 방식 (결정 필요)

| 안 | 내용 | 장점 | 비용과 위험 |
| --- | --- | --- | --- |
| **A. 기기 안 전시 + 카드 내보내기 (1차 권장)** | 태블릿을 돌려 보거나 전자칠판 발표 모드로 띄운다. 카드는 이미지로 저장·공유한다 | 서버와 개인정보 위험이 없고 지금 구조 그대로 된다 | 다른 기기의 작품이 자동으로 모이지 않는다 |
| **B. 방 코드 학급 전시관 (2차)** | 교사가 방을 열고 학생이 코드로 입장하면 카드와 스티커가 실시간으로 모인다. Cloudflare Workers + Durable Objects | 진짜 "공유"가 되고 교실 몰입이 크다 | 서버 구현과 교실 환경 검증이 필요하다 |

B를 하더라도 **녹음 파일은 서버에 올리지 않는다.** 스케치와 글만 공유하고, 목소리는 발표자 기기에서 재생한다. 프로젝트는 지금까지 백엔드 없이 정적 배포였으므로 B는 사용자의 명시 승인이 있어야 연다.

## 4. 코드베이스 분석

- 활동 진입: `src/adventure.ts:45`가 활동 9를 `inventionView`로 보내고, 실제 조작은 `src/mission-play.ts`의 설계·사용 구간(약 1200행 이후)이 맡는다.
- 완료 판정: `src/domain.ts`의 활동 10 판정, `src/mission-model.ts:42`의 시제품 시험 조건.
- **가장 큰 의존성은 마지막 복구다.** `src/final-mission.ts`의 `invention` 경로와 `src/domain.ts:147,154`가 `s.design`, `designResult`, `inventionTestView`에 묶여 있다.
- 엔딩 영상 대사(`src/story-video.ts`)가 "네가 설계한 발명품이야. 자석으로 당겨 볼게!"라고 말한다. 학생 아이디어가 자유로워지면 문구를 일반화해야 한다.
- 저장: IndexedDB `push-pull-city` 버전 1, 저장소 `saves` 하나. 녹음 파일은 저장 스냅샷과 분리해야 한다.
- 설계 관련 코드를 참조하는 곳: 테스트 8개(`coaching`, `domain`, `experiment-autoplay`, `final-review`, `inquiry`, `mechanics`, `quest`, `tablet`), 브라우저 스크립트 6개.

## 8. 데이터 구조와 저장

```ts
type Idea = {
  problem: { id: string; custom?: string };
  properties: string[];
  sketch: { strokes: Point[][]; stickers: { id: string; x: number; y: number; pole?: Pole }[]; arrows: [Point, Point][] };
  name: string; pitch: string; voiceId?: string; revision: number;
  feedback: { sticker: 'useful' | 'clever' | 'curious'; question?: string }[];
  change?: string;
};
```

- `Save`에 `idea?: Idea`를 선택 필드로 추가하고 `version`을 3으로 올린다. `validSave`와 `migrateSave`를 함께 고친다.
- **기존 저장은 깨지 않는다.** 이미 활동 9·10을 끝낸 학생은 증거와 `s.design`을 그대로 유지하고, 마지막 복구도 예전 경로로 통과한다. 새 경로는 `s.idea`가 있을 때만 쓴다.
- 녹음은 IndexedDB 버전 2의 새 저장소 `recordings`에 Blob으로 둔다. `saves` 스냅샷과 분리해서 자동 저장을 무겁게 만들지 않는다.
- 활동을 끝내도 녹음은 기기 밖으로 나가지 않는다. 전체 초기화에 녹음 삭제를 포함하고, 안내 문구에도 쓴다.

## 9. 마지막 복구 연결

`invention` 경로를 "내 장치 시험"에서 "내 발명 카드를 광장에 설치하기"로 바꾼다. 활동 내용은 원리 점검을 통과한 카드를 고르고, 내 발명이 쓴 자석 성질 하나를 설명하는 것이다. 엔딩 대사는 특정 장치에 묶이지 않게 고친다.

## 10. 오류 처리

- 마이크 권한 거부, 마이크 없음, `MediaRecorder` 미지원: 글쓰기로 바로 전환하고 완료를 막지 않는다.
- 브라우저별 형식 차이: `isTypeSupported`로 `audio/webm;codecs=opus`, `audio/mp4` 순서로 고른다.
- 저장 공간 부족: 녹음은 실패로 알리고 글 소개로 이어간다.
- 녹음 중 화면 이탈이나 탭 숨김: 녹음을 멈추고 마이크 트랙을 반드시 해제한다.

## 11. 개인정보와 안전

- 학생 목소리는 개인정보 성격이 있다. 기기 안에만 두고 서버 전송을 금지한다.
- 녹음 전 안내를 띄운다: "이름이나 학교는 말하지 않아도 돼."
- 직접 쓰는 불편과 질문은 저장 전에 길이를 제한한다. 공유 안 B를 열면 교사 숨기기 기능이 필수다.
- 교사용 미리보기 모드에서는 녹음을 저장하지 않는다.

## 12. 접근성과 기기

- 스케치판은 `touch-action: none`, 스티커는 "스티커 누르기 → 칸 누르기" 대체 조작을 둔다.
- 말하기 어려운 학생을 위해 녹음과 글쓰기를 동등한 경로로 둔다. 말을 못 하면 진행이 막히는 구조를 만들지 않는다.
- 녹음 상태는 색, 아이콘, 남은 초 숫자로 함께 보여 준다.
- 폰 가로 915×412에서 스케치판과 버튼이 모두 닿는지 확인한다.

## 14. 완료 기준과 검증

- 새 학생이 활동 9·10을 끝내고 마지막 복구와 인증서까지 도달한다.
- 이미 공방을 끝낸 저장을 불러와도 진행과 증거가 그대로다.
- 전체 초기화 뒤 녹음이 남지 않는다.
- 마이크 거부 상태로도 끝까지 갈 수 있다.
- `npm run build`, `npm test`, `npm run test:browser`, 태블릿 레이아웃 회귀가 통과한다.
- 실기기 미검증 항목: iPad Safari 녹음, 학교 태블릿 마이크 권한, 교실 소음에서의 녹음 품질.

## 15. 반목표

이렇게 되면 기술적으로 돌아가도 실패다.

- 친구 의견이 점수나 순위가 되어 비교로 끝난다.
- 그림을 못 그리는 학생이 막힌다. 스티커만으로도 완성할 수 있어야 한다.
- 자석과 상관없는 아이디어가 그대로 통과한다.
- 녹음 부담 때문에 학생이 진행을 포기한다.

## 16. 안 만들 것

로그인, 공개 랭킹, 좋아요 수 비교, 녹음 서버 업로드, 음성 자동 평가.

## 17. 롤백

작업 브랜치에서 진행하고, 5단계 전까지 기존 공방 코드를 지우지 않는다. 기존 코드는 교체 뒤 `_unused/`로 옮긴다. `version` 3 저장은 이전 코드가 읽지 못하므로, 5단계 배포 전에 이전 저장 백업을 `storage.ts`의 기존 방식대로 남긴다. 녹음 저장소 추가는 되돌려도 기존 `saves`에 영향이 없다.
