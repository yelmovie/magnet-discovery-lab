# 디자인 방향 — 밀고 당기는 도시 MVP

버전: 1.0 · 2026-09-23 · 기존 에셋 검토를 반영한 제작 기준

## 1. 한 가지 시각 방향

**자석으로 움직이는 밝고 아기자기한 과학도시.** 하늘색·아이보리·은색 건물에 자석의 빨강·파랑을 사용한다. 둥근 연구소, 말굽자석 입구, 유리 돔, 고리 구조물, 작은 운반 레일로 도시의 정체성을 만든다.

자연 테마는 사용하지 않는다. 작은 화분이나 가로수는 도시 조경으로만 쓴다. 파괴된 폐허나 어두운 사이버펑크가 아니라, 멀쩡한 도시의 장치가 멈춘 상태에서 시작한다.

## 2. 화면별 표현 규칙

| 화면 | 표현 | 연결 요소 |
|---|---|---|
| 메인 | 기존 로고와 부드러운 2D 도시 배경 | 중앙 코어·빨강/파랑 구조물 |
| 도시 탐험 / 스테이지 선택 | 비스듬한 시점의 2.5D 픽셀아트 | 같은 건물 실루엣·캐릭터·색상 |
| 10개 활동 | 정면·측면·평면 2D, 선명한 물체와 큰 조작 공간 | 각 건물의 내부라는 느낌 |
| 보고서·코어 미션 | 2D 패널과 실제 실험 결과 | 같은 자석·고리·철판 |
| 엔딩·인증서 | 2D 장면 애니메이션과 DOM 문서 | 복구된 도시와 내 발명 |

픽셀 스타일을 활동 화면까지 확장하지 않는다. 활동의 입체감 있는 그림자는 가능하지만 비스듬한 타일 월드나 자유 3D 회전은 사용하지 않는다.

## 3. 팔레트와 UI 토큰 초안

기존 샘플·캐릭터 시트를 시각적으로 읽어 선정한 초안이다. 모든 조합의 대비를 실측한 결과는 아니며 구현 때 본문 4.5:1, 큰 글자 3:1 이상을 확인한다.

| 토큰 | 값 | 사용 |
|---|---|---|
| ink | `#102B50` | 본문·제목·아이콘 외곽 |
| sky | `#DDF3FF` | 밝은 하늘·배경 |
| surface | `#FFF9EB` | 안내 카드·작업대 |
| white | `#FFFFFF` | 카드 내부·하이라이트 |
| silver | `#C0C4CC` | 자석 끝·시설 외장 |
| magnet-red | `#E53935` | 자석·밀이·강조 |
| magnet-blue | `#2E70FF` | 자석·시설 포인트 |
| action-blue | `#1756B8` | 기본 액션 버튼 |
| mission-yellow | `#FFC629` | 현재 목적·중요 지점, ink 글자와 조합 |
| restored-green | `#237653` | 복구 표시, 문자·체크와 함께 |

- UI 글꼴: 가독성 좋은 한국어 고딕 계열, 우선 시스템 글꼴. 픽셀 글꼴로 본문을 쓰지 않는다.
- 제목 36~44px, 핵심 안내 22~26px, 본문 18~20px, 보조 정보 16px 이상을 가로 태블릿 기준으로 시작한다.
- 공통 간격: 8 / 12 / 16 / 24 / 32px.
- 카드 모서리 20~24px, 버튼 16~20px. 얕은 아래 그림자로 누를 수 있는 형태를 보여 준다.
- 주요 버튼 높이 64px 목표, 보조 버튼·입구 조작 hit 영역 최소 48×48px.
- 같은 화면의 주요 진행 버튼은 하나. 기록·힌트·도시 복귀는 보조 액션이다.
- 초록/빨강만으로 성공·실패를 표시하지 않는다. 장치 반응과 짧은 문장으로 설명한다.

## 4. 메인 화면

- 상단 중앙: 기존 제목 로고. 이미지에 단원명을 중복 덧붙이지 않는다.
- 배경: 둥근 연구 시설, 중앙 코어, 말굽자석 형태가 보이는 밝은 도시의 2D 전경.
- 하단 중앙: 시작하기. 저장이 있으면 이어하기를 기본 액션으로 하고 새로 시작은 보조 액션.
- 밀이·당이는 하단 좌우에 자연스럽게 배치하고 버튼 영역을 가리지 않는다.
- 단원 표시는 별도 DOM 텍스트로 한 번만 넣는다.
- 로고의 광택·입체감은 브랜드 이미지로 유지할 수 있다. 실시간 3D 렌더링을 뜻하지 않는다.

## 5. 스테이지 선택: 도시 탐험 화면

### 공간 구성 초안

아래는 제작을 위한 배치도이며 최종 픽셀아트가 아니다. 중앙 광장을 기준으로 여섯 입구를 연결한다.

```text
┌───────────────────────────────────────────────────────┐
│ 도시 이름 / 복구 상태             연구 가방 · 설정     │
├───────────────────────────────────────────────────────┤
│       [힘 실험 연구소]        [극성 복원 센터]          │
│            ╲                     ╱                    │
│ [생활 자석 조사국] ─ [코어 광장 · 당이] ─ [원격 제어]  │
│            ╲           │         ╲                    │
│             ╲       시작 지점    [시민 발명 공방]      │
│                                                       │
├───────────────────────────────────────────────────────┤
│ 현재 목적: 조사국에서 자석의 단서를 찾아보자           │
└───────────────────────────────────────────────────────┘
```

도시 콘텐츠 영역의 정규화 좌표 초안. 실제 건물 크기·입구 위치는 충돌과 가독성을 보며 조정한다.

| 대상 | 중심 x/y | 모양과 식별 장치 |
|---|---|---|
| 조사국 | 0.16 / 0.48 | 빨간 말굽자석 입구, 보관함 전시창 |
| 힘 실험 연구소 | 0.32 / 0.22 | 파란 둥근 연구소, 투명 실험창·분류 컨베이어 |
| 극성 복원 센터 | 0.66 / 0.22 | 빨강·파랑 고리가 층층이 보이는 낮은 타워 |
| 원격 제어 구역 | 0.85 / 0.48 | 수조 돔, 작은 카트 레일 |
| 시민 발명 공방 | 0.72 / 0.77 | 노란 차양, 부품 진열대, 완성품 전시대 |
| 중앙 코어 | 0.49 / 0.42 | 고리형 관제탑. 앞쪽 광장에 당이 배치 |
| 시작 위치 | 0.42 / 0.82 | 표지와 바닥 화살표, 첫 목적지가 보이는 위치 |

- 건물은 지붕보다 입구가 잘 보여야 한다. 모든 입구 앞에 캐릭터가 설 공간을 둔다.
- 건물을 가르는 이동 경로를 만들지 않는다. 건물 앞 도로가 중앙 광장으로 이어진다.
- 현재 목적지에는 노란 작은 표시와 명확한 이름을 사용한다. 모든 건물에 큰 말풍선을 동시에 띄우지 않는다.
- 건물 이름은 읽을 수 있는 DOM 표지로 짧게 표시하고 전체 미션명은 입장 카드에서 보여 준다.
- 밀이가 입구에 도착하면 `장소 이름 / 한 줄 의뢰 / 입장` 카드를 연다. 닫고 계속 탐험할 수 있다.
- 키보드나 보조 이동 버튼도 제공한다. 시설 선택은 같은 입구까지 걸어가는 경로를 사용해 탐험 경험을 유지한다.

### 픽셀아트 제작 기준

- 논리 도시 화면 480×240에서 구성, 2배·3배 등 정수 배율 우선.
- 길·바닥 타일 기본 16px 계열, 캐릭터 한 프레임 24×32px를 출발점으로 삼는다.
- 캐릭터 4방향 × 걷기 3프레임. 각 방향의 기본 프레임을 서 있기에도 사용한다.
- 건물은 48~96px 폭의 독립 스프라이트. 높은 지붕은 위쪽 시설을 가리지 않게 조절한다.
- 외곽선·그림자·광원은 통일한다. 광원은 좌측 위, 바닥 그림자는 우측 아래.
- 이미지를 단순히 축소한 거친 그림 대신 픽셀 크기에 맞춘 실루엣을 제작한다.
- 가까운 시설끼리 빨강·파랑만 다르게 하지 않고 형태·소품·간판도 구분한다.

### 복구 상태의 변화

| 진행 | 눈으로 확인하는 변화 |
|---|---|
| 0% | 시설 형태는 온전하지만 표시등·레일·장치가 멈춤 |
| 20% | 조사국 보관함이 닫히고 잠금 표시가 켜짐 |
| 40% | 연구소 컨베이어가 철 물체를 분리하며 움직임 |
| 60% | 센터 고리 간격과 표시등이 복구됨 |
| 80% | 수조가 맑아지고 카트가 짧은 레일을 왕복함 |
| 95% | 공방 전시대에 학생이 설계한 장치가 놓임 |
| 100% | 코어 상태가 바뀌고 도시 연결 표시가 모두 켜짐 |

시설마다 기본 스프라이트와 복구 오버레이를 조합한다. 진행 단계마다 도시 전체 이미지를 새로 로딩하지 않는다. 자석에서 전기가 생성되는 과학 설명처럼 보이는 효과는 넣지 않는다.

## 6. 2D 활동 공통 레이아웃

- 상단: 도시 복귀, 현재 장·활동 이름, 연구 기록.
- 중앙 좌측~중앙: 화면 55~65%의 실험 대상과 조작 영역.
- 우측: 현재 할 일 한 개와 관찰 결과. 패널을 세 겹 이상 쌓지 않는다.
- 하단: 현재 선택 대상에 필요한 조작과 다음 행동. 버튼 최대 3~4개를 기본으로 한다.
- 1024×768에서는 기록 패널을 서랍으로 접고 실험 대상을 유지한다.
- 진행은 단순 `7/10`보다 `4장 · 수조 청소`처럼 현재 하는 일을 우선 표시한다.
- 설명이 많으면 전체 화면을 설명 카드로 덮지 않고 당이의 짧은 질문과 기록 서랍으로 분산한다.

공통 UI 상태: 기본 / 포커스 / 눌림 / 사용 불가 / 실행 중 / 완료 / 다시 시도. 사용 불가 버튼에는 필요한 행동을 인접한 문장으로 표시한다.

## 7. 캐릭터 기준

실제 파일을 확인한 결과 과거 문서와 시트의 형태가 다르다. 이번 디자인은 제공된 캐릭터 시트를 우선한다.

| 캐릭터 | 실제 시트 기준 | 역할과 표현 |
|---|---|---|
| 밀이 | 빨간 U자 몸, 은색 끝, 흰 장갑, 빨간 운동화 | 활동적. 도시 이동, 조작 안내, 발견 반응 |
| 당이 | 빨강·파랑 U자 몸, 은색 끝, 기록판·연필 | 차분함. 의뢰·기록·비교·보고 |

- 활동 화면에 필요한 표정은 기본·궁금함·생각·기쁨 4종부터 준비한다.
- 지도에서 밀이는 걷기 프레임, 당이는 대기·대화 프레임만 우선 제작한다.
- 마스코트의 몸 색과 형태는 캐릭터 디자인이다. 과학 실험에 쓰는 자석은 N/S 표시를 별도로 정확하게 그린다.
- 일부 샘플에 보이는 추가 고리 캐릭터 등은 MVP의 별도 NPC로 늘리지 않는다.

## 8. 확인한 기존 에셋과 사용 방법

아래 경로는 프로젝트 루트 기준이다. 원본 이름과 파일은 그대로 보존한다.

| 파일 | 확인한 내용 | 사용 방침 |
|---|---|---|
| `ChatGPT Image 2026년 9월 23일 오후 09_58_17.png` | 1774×887, 제목 로고 | 메인 로고 후보. 가장자리와 실제 알파 상태를 구현 시 확인 |
| `ChatGPT Image 2026년 9월 23일 오후 09_58_25 (1).png` | 1672×941, 밀이 시트 | 정체성·표정·색 기준. 시트 전체를 캐릭터 스프라이트로 사용하지 않음 |
| `ChatGPT Image 2026년 9월 23일 오후 09_58_25 (2).png` | 1672×941, 당이 시트 | 기록 소품과 빨강·파랑 형태 기준 |
| `ChatGPT Image 2026년 9월 23일 오후 09_56_38 (1).png` | 1672×941, 물건 해부실 샘플 | 큰 대상·버튼·샘플 색감 참고. 3D 회전 UI는 복제하지 않음 |
| `ChatGPT Image 2026년 9월 23일 오후 09_56_51 (7).png` | 1672×941, 수조 활동 샘플 | 정면 수조·외부 자석·큰 조작 영역 참고. 중복 캐릭터와 과한 패널은 정리 |
| `ChatGPT Image 2026년 9월 23일 오후 09_58_06 (6).png` | 1672×941, 고리 장치 연구실 배경 | 은색·유리·고리 시설 분위기 참고. 코일·발전 표현은 학습 기능에 도입하지 않음 |

그 외 PNG와 확장자 없는 파일은 존재를 확인했으나 모두 시각 검수한 것은 아니다. 이름만 보고 활동·용도를 확정하거나 PNG로 무조건 이름을 바꾸지 않는다. 실제 필요한 장의 구현 시 형식·내용·중복을 확인한다.

현재 확인된 샘플·시트는 제작 참고 자료다. 곧바로 사용 가능한 투명 개별 캐릭터, 도시 타일셋, 걷기 스프라이트가 확보됐다고 간주하지 않는다.

## 9. MVP 신규·가공 에셋 목록

| 그룹 | 최소 준비 단위 | 검수 기준 |
|---|---|---|
| 도시 바닥 | 도로·보도·광장·레일·테두리 타일 | 연결 이음새, 걸을 수 있는 영역과 시각 일치 |
| 도시 건물 | 5개 시설 + 코어, 복구 오버레이 6종 | 서로 다른 실루엣, 입구 위치, 가림 |
| 도시 캐릭터 | 밀이 12프레임, 당이 대기·대화 | 발 위치 고정, 프레임별 크기 일관 |
| 2D 캐릭터 | 밀이·당이 각 4표정 | 배경 없는 개별 자산, 시트와 동일 정체성 |
| 1장 | 보관함·책갈피, 내부 레이어·자석 부품 | 자석 위치와 움직이는 부분 분리 |
| 2장 | 재료 6종, 막대자석·종이판 | 재료 구별, N/S 글자는 DOM/SVG |
| 3장 | 기준·미지 자석, 고리·지지 막대 | 극 상태에 맞춰 뒤집기 가능 |
| 4장 | 수조·오염 마스크·패드, 카트·레일 | 배경과 움직이는 대상 분리 |
| 5장·최종 | 두 문제의 부품, 코어 패널·가동 손잡이 | 부품 연결 위치와 판정 기준 일치 |

단순 버튼·슬롯·N/S 표시·선택 윤곽은 CSS/SVG로 만든다. 일러스트 제작·편집이 필요할 때 원본을 참고하여 별도로 작업하며 이번 설계 단계에서 이미지 생성은 실행하지 않았다.

## 10. 디자인 검증 기준

1. 메인→도시→활동에서 같은 캐릭터·시설·색의 연결성이 보인다.
2. 스테이지 화면이 번호 버튼 목록이 아니라 캐릭터 이동과 건물 입장으로 작동한다.
3. 작은 화면에서도 현재 목적지·캐릭터·입구를 구별한다.
4. 픽셀 캐릭터와 건물의 픽셀 크기가 일관되고 UI 글자는 선명하다.
5. 멈춤/복구를 색 외에 장치 동작·모양·상태 문장으로 구별한다.
6. 버튼과 제목이 원본 샘플 이미지의 글자와 중복되지 않는다.
7. 실험 대상보다 캐릭터·장식·미션 카드가 커지지 않는다.
8. 대비, 실제 터치 크기, 겹침·잘림은 구현 화면에서 측정한다. 이 문서는 시각 검수 통과 보고서가 아니다.
