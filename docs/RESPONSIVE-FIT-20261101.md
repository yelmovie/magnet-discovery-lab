# 한 화면 맞춤과 크게 보기 · 2026-11-01

2026-11-05: 가로 820~1000px의 폰·폴드에서는 지도와 실험대가 화면 폭에 맞는다. 수첩·인증서처럼 긴 화면은 세로로 읽을 수 있다. [최신 실측](reviews/RELEASE-REVIEW-20261105.md).

## 원칙

- 평소에는 모든 화면이 스크롤 없이 한 화면에 들어간다. 버튼이 잘리거나 서로 겹치지 않는다.
- 화면이 레이아웃이 버틸 수 있는 크기보다 작아지면(브라우저 확대 = 크게 보기, 폰 가로) 무대가 **860×560**을 유지하고 페이지에 스크롤바가 생긴다. 찌그러지거나 잘리지 않는다.
- 세로 화면(폭 759px 이하)은 기존의 세로 스크롤 배치를 그대로 쓴다.
- 팝업은 화면보다 길면 팝업 안에서 스크롤된다.
- 활동 화면의 '장치 살펴보기' 창에는 **그림 크게 보기** 버튼이 있다. 누르면 그림이 창 폭 전체로 커지고(원본보다 최대 1.3배), 그림 틀 안에서 가로·세로 스크롤바로 둘러본다.

## 구현

| 파일 | 내용 |

| `src/mission-play.ts` | 5·9활동 조각 시작 좌표를 버튼과 안 겹치게 조정 |
| `src/fit-report.css` | 보고서: 제목 → 탭 → 발견 카드 → 버튼 줄 세로 배치, 높이가 모자라면 카드 안만 스크롤. 인증서: 1100px 이하에서도 인증서·패널 나란히, 인증서는 남은 높이에 1600:1062 비율로 맞춤, 인쇄 버튼은 화면에서만 인증서 아래로(인쇄 결과는 그대로) |

| `learning-ux.css` | 좁은 가로 화면 전용 블록 삭제(무대 최소 크기로 대체) |

## 측정

`node scripts/layout-audit.cjs [주소] [--only 화면] [--sizes 1280x800,...]` — 상태 45개 × 기본 화면 크기 12개(1920×1080 ~ 375×812, 확대 125·150·200% 상당 포함)를 띄워 페이지 스크롤, 잘린 버튼, 겹친 버튼, 잘린 글자, 44px 미만 터치 영역, 콘솔 오류를 잰다. 결과는 `--out` 폴더(기본 `test-results/layout-audit/`)의 `summary.md`·`results.json`·`shots/`.
