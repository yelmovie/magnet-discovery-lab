# 밀고 당기는 도시 태블릿 탐구 경험 개편 설계

작성일: 2026-10-16 · 개정: 학생 눈높이와 성취기준 검토 반영  
상태: 2026-10-18 실제 앱 반영. [최신 구현·검증 기록](TABLET-IMPLEMENTATION-20261018.md) 참고. 아래 10월 16일 시안 검증은 당시 이력이다.  
대상: 초등 4학년. 개인 또는 두 학생이 한 태블릿을 함께 사용.

## 1. 제품 목표와 이번 개정

**긴 설명을 읽기 전에 물체를 움직이고, 반응을 보면서 이유를 알아낸다.**

앱이 담당하는 가치는 연속 조작·즉시 반응·같은 조건 재시험·내 결과 비교다. 과학적 사고는 학생이 하고, 위치 고정·기록 저장·비교 짝 찾기 같은 관리 절차는 앱이 처리한다. 터치 외에도 마우스·키보드·선택 후 배치로 같은 학습을 완료할 수 있다.

기존 5개 구역·10개 활동, 도시 탐험·연구 기록·보고서·최종 미션·엔딩·인증서를 유지한다. 도시만 기존 2.5D 표현을 쓰고 활동은 2D로 구성한다. 기존 기술과 에셋, IndexedDB를 활용한다. 새 서버·계정·범용 물리 엔진·3D·필수 센서·제한시간·실패 감점은 추가하지 않는다.

### 검토 항목별 반영

| 발견한 문제 | 이번 설계의 결정 |
|---|---|
| 질문·설명·관찰·하단 안내가 같은 말을 반복 | 질문 1개, 현재 행동 1개, 행동 뒤 결과 1개로 역할 분리 |
| 기록 고정·선택·증거 연결 절차가 복잡 | 앱이 자동 저장·비교·조건 고정. 학생은 물체만 조작 |
| 발명 문구는 자석 이동인데 그림은 철판 이동 | 실제 바뀐 부품 좌표로 그림·설명 생성. 철판은 고정, 자석만 이동 |
| 자석·철판이 덮개와 떨어져 보임 | 자석은 덮개에 부착, 철판은 몸체에 고정, 접촉 위치를 확대 |
| 배송 수레의 자석이 보이지 않음 | 수레 부착 자석과 N/S를 항상 표시. 철 부품과 자석을 구별 |
| 시험 전에 결과를 제목에서 알려줌 | 시험 전은 예상 질문, 시험 후에만 결과 표시 |
| 글자가 13~15px로 작음 | 학생용 설명·기록 16px 이상, 조작 버튼 18px 이상 |
| 1024에서 기록 서랍이 없음 | 기록은 기본 닫힘. 넓은 화면에서도 선택해서 열기 |
| 처음 성공해도 두 번째 설계를 의무 제작 | 성공 장치 1개와 짧은 설명이 기본. 추가 비교·다른 설계는 선택 도전 |
| 최종 미션이 네 활동의 반복 시험 | 기본은 고장 난 한 구간만 조작. 전체 구간 직접 복구는 선택 도전 |
| 나침반 관찰 연결 누락 | 활동 5의 선택 탐구 및 교실 실물 활동으로 연결 |
| 관찰 결과를 앱이 대신 설명 | 구역 마무리에서 자신의 실험 그림으로 짧게 설명 |

## 2. 교육과정과 학습 확인

근거: 교육부 고시 제2022-33호 별책 9 과학과 교육과정의 초등 3~4학년군 ‘자석의 이용’. 아래는 원문 인용이 아닌 설계 대응 요약이다.

[교육부 공식 고시 및 별책 9 첨부](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458&lev=0&search=)

| 성취기준 취지 | 활동 | 학생이 남기는 학습 결과 |
|---|---|---|
| [4과09-01] 물체와 자석의 반응을 관찰하고 힘의 특징을 말하기 | 1~4, 7 | 자신의 재료·거리 비교 그림을 보고 “닿지 않아도 당겼어” 등 관찰한 특징 표현 |
| [4과09-02] 자석 사이 현상을 극과 관련지어 설명하기 | 5·6·8 | 마주 보는 같은/다른 극과 밀림/끌림을 자신의 실험에 연결 |
| [4과09-03] 생활을 편리하게 하는 자석 장치 설계하기 | 2·9·10 | 해결할 불편 선택, 부품 배치, 이용한 자석의 성질과 편리해진 점 설명 |

### 필수와 선택

- **기본 학습:** 직접 관찰 → 필요한 비교 → 장치 구상 → 자신의 결과를 짧게 설명.
- **게임의 작동 확인:** 간단한 가상 시험으로 설계 결과를 보되, 여러 성공 시험을 모두 교육과정상 필수라고 표현하지 않는다.
- **선택 도전:** 세 번째 고리 주문, 다른 발명 설계, 추가 내구 시험, 최종 전 구간 직접 조작. 기본 완료 뒤에 제시하고 수료를 막지 않는다.
- 공식 고려 사항은 장치 설계가 반드시 실제 만들기로 이어져야 함을 뜻하지 않는다고 밝힌다. 실물 제작·정밀 조작 성공을 성취의 유일한 근거로 삼지 않는다.
- 자기장·자력선·정량 공식·발전 원리를 가르치지 않는다.

### 학생의 설명 확인

모든 활동에 퀴즈를 추가하지 않는다. 구역의 두 번째 활동을 마칠 때 자신의 실험 그림과 질문 하나를 제시한다.

| 구역 | 마무리 질문 | 쉬운 표현 방법 |
|---|---|---|
| 생활 | 무엇이 덮개를 붙잡았을까? | 자신의 그림에서 자석과 철판 가리키기 |
| 재료·거리 | 자석이 닿기 전에도 움직였니? | 실제 비교 장면 + 짧은 문장 선택/짝에게 설명 |
| 극·고리 | 어떤 극끼리 마주 보니 밀렸니? | 자신의 배열에서 두 면 선택, “같은 극 → 밀림” 연결 |
| 원격 제어 | 손대지 않고 어떻게 움직였니? | 자석의 이동과 패드/수레의 반응을 짚어 설명 |
| 발명 | 누구의 어떤 불편을 해결했니? | 의뢰 그림과 내 장치 그림을 보고 사용 목적 설명 |

문장 선택은 한 번의 정답 맞히기 점수가 아니라 관찰 회상의 보조다. 틀리면 관련 장면을 보여 주고 다시 말해 보게 한다. 짝에게 설명한 사실을 눌렀다고 앱이 학생의 이해를 자동 채점했다고 주장하지 않는다. 교사의 관찰을 병행한다.

### 나침반 연결

원문의 탐구 활동에 제시된 나침반 관찰은 활동 5의 “더 해 보기”에 둔다. 기준 자석을 움직이면 나침반 바늘의 방향이 바뀌는 모습을 관찰한다. 자석을 아주 가까이 둔 단순 모형임을 교사용 안내에 설명하고 지구 자기장이나 수치 해석을 가르치지 않는다. 단원 전체 수업에서는 교사가 이 탐구 또는 실물 나침반 관찰을 포함한다. 10개 기본 활동을 완료했다는 사실만으로 단원 내 모든 탐구를 했다고 표시하지 않는다.

## 3. 한눈에 이해하는 공통 화면

### 정보의 우선순위

화면에 계속 보이는 학습 문장은 **질문 하나와 현재 행동 한 줄**이다. 반응 뒤에는 행동 안내 자리에 짧은 결과를 보여 주고, 다음 행동이 필요할 때 안내를 갱신한다. 같은 내용의 보조 제목·하단 설명·관찰 카드 중복은 제거한다.

```text
┌─────────────────────────────────────────────────────┐
│ ← 도시          힘 실험 연구소        내 실험 기록 │
│ 종이가 있어도 클립이 움직일까?                2 / 3 │
├─────────────────────────────────────────────────────┤
│                                                     │
│                크게 잡고 움직이는 물체              │
│                  자석   종이   클립                  │
│                                                     │
│       이동할 대상만 테두리 / 움직일 수 없는 대상 고정 │
├─────────────────────────────────────────────────────┤
│ 종이를 두 물체 사이에 넣어 봐.       [종이 넣기]     │
└─────────────────────────────────────────────────────┘
```

- 가로 1280×800·1280×720·1024×768에서 질문·실험대·필수 버튼을 스크롤 없이 표시한다.
- 헤더 56px, 질문 64px, 조작대 88px을 시작값으로 사용하고 나머지를 실험대에 배정한다. 실제 viewport와 safe-area로 계산한다.
- 기존의 고정 우측 설명·보상 패널을 없앤다. 기록은 버튼으로 여는 서랍이다.
- 1024와 낮은 가로 화면에서는 상세 기록 서랍을 반드시 닫힌 상태로 시작한다.
- 서랍이 열리면 뒤 실험의 입력·자동 진행을 멈춘다. 닫기·Escape·바깥 누르기로 닫고 원래 버튼에 포커스를 돌린다.
- 세로에서는 물체 크기를 유지하고 실험대와 하단 조작을 세로 배치한다. 상세 기록만 내부 스크롤한다.
- 메인·도시·기록·최종·엔딩에서도 같은 버튼 위치와 용어를 사용한다.

### 글자와 조작

| 항목 | 기준 |
|---|---|
| 질문 | 24~30px, 최대 두 줄 |
| 행동·결과·주요 버튼 | 18~20px, 한 번에 한 행동 |
| 물체 라벨·기록 | 최소 16px |
| 터치 | 최소 48×48 CSS px, 드래그 물체는 56~72px 이상 |
| 선택 대상 | 테두리·손잡이·눌림 피드백. 첫 조작 전에 짧은 화살표 시범 1회 |
| 고정 대상 | 손잡이와 눌림 효과 없이 표시. 필요하면 “그대로” 자물쇠 그림 |
| 색 | 극은 N/S 문자 병기. 성공·실패도 그림·문자로 구분 |
| 캐릭터 | 안내 옆 한 명, 물체를 가리지 않음 |
| 배경 | 조작면은 밝은 단색. 도시 그림은 가장자리 또는 전환 장면 |
| 이동 대안 | 물체 선택 후 위치 누르기, 방향 버튼, 방향키 |
| 되돌리기 | “처음 위치”는 현재 시험만 초기화. 기록·완료 상태를 지우지 않음 |

학생에게 “탐색·적용·시험 위치 고정·증거 연결”을 조작 용어로 노출하지 않는다.

| 교체 전 | 학생용 표현 |
|---|---|
| 탐색 → 비교 → 적용 | 해 보기 → 비교하기 → 고쳐 보기 |
| 내가 남긴 증거 | 내 실험 기록 |
| 시험 위치 고정 | 자석은 여기 그대로 |
| 바꾼 조건: 간격 | 거리만 바꿨어 |
| 원리 증거 연결 | 왜 잘 붙었을까? |
| 두 설계에 같은 시험을 적용 | 두 장치를 똑같이 흔들어 보자 |

### 앱이 자동으로 처리할 일

- 반응이 관찰되면 해당 조건·결과를 기록한다. 학생에게 매번 저장 버튼을 요구하지 않는다.
- 종이 비교를 시작하면 직전 가까운 시험의 자석·클립 시작 위치로 복원한다.
- 비교할 기록은 앱이 유효한 짝을 골라 보여 준다. 기록 관리·변인 검증은 교사용/내부 로직이다.
- 성공 시 결과를 먼저 볼 시간을 준다. 자동으로 다음 활동으로 넘기지 않고 다음 버튼을 제공한다.
- 도움은 관찰할 곳 → 조절할 조건 → 짧은 시범 순서로 제공한다.
- 기본 안내는 정답 극·위치보다 목표와 조작 방법을 알려 준다.
- 포인터 취소·두 번째 손가락·회전 시 마지막 유효 위치를 보존한다.
- 멀티터치·센서·미세한 흔들기 속도를 필수로 요구하지 않는다.

## 4. 전체 화면과 열 가지 활동

### 메인과 도시

메인의 기본 버튼은 “탐험 시작”, 저장이 있으면 “이어서 하기”다. 첫 화면에서 이야기 두 문장 이상을 읽게 하지 않는다. 도시는 현재 갈 건물 한 곳만 강조하고 “여기서 시작”을 표시한다. 건물을 누르면 입구까지 자동 이동하고 “들어가기”를 보여 준다. 길찾기 실수를 학습 조건으로 삼지 않는다. 보상과 복구율은 이동·구역 완료 장면에서 보여 주고 실험 중에는 숨긴다.

### 활동 1 숨어 있는 자석 찾기

- 첫 질문: “어디에 자석이 숨어 있을까?”
- 처음에는 예상 위치만 누르게 한다. 표시하면 손잡이만 강조하며 “손잡이를 위로 올려 봐.”로 갱신한다.
- 열고 난 뒤에만 자석 꺼내기 안내를 보여 준다. 자석과 철판이 맞닿던 위치를 남긴다.
- 보관함·책갈피 모두 관찰하되 두 번째 물건에서는 도움을 줄인다.
- 완료는 두 물건의 자석 확인. 최초 예상과 확인 위치를 자동 보존하며 별도 원리 문제를 붙이지 않는다.

### 활동 2 자꾸 열리는 물건 수리

- 질문: “어떻게 하면 덮개가 붙어 있을까?”
- 첫 장치에서 자석 없이 닫기 → 앱이 일정하게 흔들기 → 자석 넣고 닫기 → 같은 흔들기 자동 실행.
- 자석은 덮개 안쪽에, 철판은 몸체에 부착한다. 닫힐 때 두 부품이 만나는 위치를 명확히 보여 준다.
- 두 번째 물건은 학생이 자석을 놓아 수리한다. 조작 도움은 필요할 때만 제공한다.
- 완료: 유무 비교와 두 번째 물건 수리. 구역 마무리에서 어떤 부품이 붙잡았는지 자신의 그림으로 설명한다.

### 활동 3 철 부품 분류 작전

- 질문: “어떤 물체가 자석을 따라올까?”
- 여섯 물체를 3개씩 두 차례 제시한다. 현재 선택한 재료 이름을 크게 표시한다.
- 첫 단계 바구니 이름은 “내 예상”. 검사 뒤에는 “확인한 결과”로 바뀌어 예상과 최종 분류를 구별한다.
- 검사한 철은 자석을 따라 움직이고 알루미늄·나무·플라스틱·고무 표본은 움직이지 않는다.
- 맞게 예상한 물체는 자동 확인되어 다시 옮길 필요가 없다. 틀린 예상만 학생이 결과에 맞게 옮긴다.
- 완료: 여섯 물체의 검사·최종 분류. 철과 알루미늄 장면은 앱이 자동으로 짝지어 보여 준다.

### 활동 4 손대지 않고 클립 움직이기

대표 체험 1. 자유 접근 중에 클립이 반응하고 필요한 비교는 자동으로 이어진다.

1. 질문 “가까이하면 클립이 움직일까?” → 자석을 직접 움직인다. 먼 조건과 가까운 조건의 관찰은 자동 기록한다.
2. “종이도 넣어 볼까?”를 누르면 같은 가까운 시작 거리로 자동 복원한다. 자석을 학생이 다시 정렬하지 않는다.
3. 질문 “종이가 있어도 클립이 움직일까?” → 종이만 움직일 수 있다. 손으로 넣거나 “종이 넣기” 버튼을 사용한다.
4. 앱이 같은 시작 상태의 결과를 나란히 보여 준다. 학생은 “종이가 있어도 움직였어” 등 자신의 관찰을 표현한다.
5. 위치가 달라진 클립을 움직이는 적용은 짧은 후속 장면으로 제공하며 기록 관리 단계를 끼우지 않는다.

- 필수 관찰: 판 없음의 멀리·가까이, 같은 시작 거리의 종이 있음.
- 자유 탐색 복귀는 “다시 해 보기”에서 제공한다. 잠긴 자석을 억지로 끌어 잠금 해제 메뉴를 찾아야 하지 않는다.
- 클립이 움직인 뒤의 현재 거리와 시험 시작 거리를 혼동하지 않도록 비교는 항상 같은 시작 상태에서 재생한다.
- 정밀 거리·힘 수치는 쓰지 않는다. 이 실험의 얇은 종이에 대해 관찰한다.

### 활동 5 사라진 극 표시 복원

- 질문: “이쪽 끝은 N극일까, S극일까?”
- 먼저 표시된 자석으로 같은 극·다른 극의 반응을 관찰한다. 기준 자석을 뒤집으면 전체 회전과 마주 보는 두 끝을 함께 강조한다.
- 회색 자석 2개의 표시를 복원한다. 한쪽을 선택하면 반대 끝은 반대 극으로 함께 표시한다.
- 비교 반응은 자동 기록하고 오류 시 상충하는 관찰 장면을 다시 보여 준다. 답을 무작정 반복 선택하는 방식은 피한다.
- 구역의 짧은 설명은 활동 6 뒤에 통합한다.
- “더 해 보기: 나침반”에서 자석의 위치와 극에 따라 바늘의 방향이 달라지는 현상을 관찰하거나 교실 실물 활동으로 연결한다. 항상 같은 끝이 자석 쪽을 향한다고 설명하지 않는다.

### 활동 6 고리자석 수리 의뢰

- 첫 질문: “고리 사이를 띄워 볼까?”
- 처음에는 고리 2개만 보여 준다. 하나를 뒤집고 놓아 붙음·밀림과 마주 보는 면을 연결한다.
- 다음에는 고리 3개 중 한 경계만 바꾸는 주문을 준다. 세 가지 주문을 처음부터 동시에 보여주지 않는다.
- 기본 완료: 두 고리 반응 비교와 세 고리의 한 가지 새 주문 해결.
- 나머지 배열·눌렀다 놓기 탐구는 “더 해 보기”. 기본 수료 조건에 포함하지 않는다.
- 비자성 지지 막대와 받침을 항상 그린다. 설명은 자신의 배열에서 두 면을 짚는 방식으로 확인한다.

### 활동 7 수조 청소 구조 작전

- 질문: “수조 안을 손대지 않고 닦아 볼까?”
- “밖” 자석과 “안” 패드를 구별하고 유리를 사이에 둔 작은 단면 그림을 함께 보여 준다.
- 손으로 잡을 수 있는 것은 바깥 자석 하나다. 내부 패드는 자석의 이동에 따라온다.
- 거리 때문에 분리되면 남은 패드를 강조하고 “자석을 패드 가까이 가져가 봐.” 한 줄만 보여 준다.
- 학생에게 85% 계산을 요구하지 않는다. 얼룩 3구역과 남은 얼룩 강조로 진행을 알려 준다. 내부의 85% 기준은 유지할 수 있다.
- 완료: 기준 청소율. 일부러 실패·분리를 경험해야 하는 조건은 없다.

### 활동 8 자석 택배를 부탁해

- 질문: “수레를 노란 곳까지 보내 볼까?”
- 수레 부착 자석의 N/S와 철 화물은 다른 물체로 표현한다. 극을 바꿔 미는 대상은 수레의 자석이다.
- “앞·뒤”만 쓰지 않고 그림 속 위치를 가리키며 “수레 오른쪽에서 당겨 봐.”처럼 안내한다.
- 첫 두 구간은 끌기·밀기를 관찰하고 마지막은 반대 방향으로 스스로 운반한다.
- 틀린 극에서도 반대 움직임이 나타나야 한다. 미션 정답 여부로 현상을 숨기지 않는다.
- 정차 구역은 넓게 잡고 자석을 떼는 행동으로 멈추게 한다. 한 번의 지나침을 전체 재시작으로 처리하지 않는다.
- 모형의 마찰에 의한 정차를 모든 실제 물체의 즉시 정지 법칙처럼 설명하지 않는다.

### 활동 9 시민을 위한 발명 설계

- 질문: “어떤 불편을 고쳐 줄까?”
- 그림 의뢰 2개: 자꾸 열리는 우편함 / 손이 닿지 않는 통 속 부품.
- 몸체는 준비해 둔다. 학생은 자석과 상대 부품의 종류·배치를 선택한다.
- 처음부터 극·높이·거리·재료를 모두 메뉴로 열지 않는다. 부품 배치 → 필요한 때 뒤집기·부품 바꾸기를 순서대로 노출한다.
- 여러 유효 배치를 인정하며 조립 홈은 안내용이다. 실제 좌표·방향으로 시험한다.
- 완료: 부품을 배치한 시험 가능한 설계. 처음부터 작동해야 시험실에 갈 수 있는 조건은 없다.

### 활동 10 내 발명품 사용 시험

대표 체험 2. 자기 설계의 한 가지 사용 시험과 설명을 기본으로 한다.

- 시험 전 질문: “내 장치가 잘 작동할까?” 결과를 제목에서 미리 말하지 않는다.
- 우편함은 학생이 덮개를 닫으면 같은 흔들기 동작을 앱이 수행한다. 자석은 덮개에 따라 움직이며 철판은 몸체에 고정된다.
- 원격 도구는 한 방향 운반이 기본이고 반대 방향·추가 내구 시험은 선택이다.
- 실패하면 해당 부분만 강조하고 “자석을 더 가까이 놓아 볼까?”처럼 도움을 요청할 때 제시한다.
- 수정 후 같은 시험을 앱이 재실행하고 최초 설계와 현재 설계의 실제 차이를 보여 준다. “자석 이동”이라고 쓰면 그림도 자석만 움직여야 한다.
- 처음 성공한 학생은 바로 자신의 장치와 사용 목적을 설명하고 기본 완료한다. 두 번째 설계나 실패를 강요하지 않는다.
- 기본 완료: 현재 버전의 장치 사용 확인 + 해결할 불편·자석 역할에 대한 짧은 표현.
- 선택: “다른 방법도 해 볼래?”에서 추가 설계·비교·다른 방향 운반. 별도 점수·수료 제한은 없다.
- 기록을 드래그해 연결하는 절차는 삭제한다. 관련 기록은 자동으로 붙이고 학생은 그림을 보며 설명한다.
- 설계 수정 시 과거 성공을 현재 성공으로 재사용하지 않는다.

## 5. 최종 미션과 마무리 화면

### 기본 모드와 선택 도전

전체 연결은 **철 부품 찾기 → 자석 배송 → 고리 받침 → 내 장치**다. 기본 모드에서는 이전에 검증한 구간을 짧게 재생하고, 이번에 고장 난 한 구간만 크게 펼쳐 학생이 해결한다. 기본 고장 구간은 내 발명 장착·작동이며 수업 설정에서 배송 또는 고리를 선택할 수 있다.

- 전체 연결도는 작은 진행 그림으로만 표시한다. 현재 조작 대상은 하나다.
- 기존 기록 재생을 이번에 학생이 새로 해결한 성공 증거로 세지 않는다.
- “내 설계 쓰기”는 장착만 한다. 학생이 장치를 작동시켜야 해당 구간이 끝난다.
- 수레에는 부착 자석의 양 끝을 보이고 철 화물은 별도 그림으로 그린다.
- 고리 받침은 비자성 막대가 있는 장치다.
- 실패 시 현재 구간만 재시도한다. 이미 끝낸 네 활동을 처음부터 반복시키지 않는다.
- 기본 완료 뒤 “전부 고쳐 보기”를 선택하면 네 구간을 직접 해결할 수 있다.
- 우편함과 원격 운반 설계 모두 최종 미션에서 사용할 수 있다.
- 도시 불빛은 이야기의 복구 표시다. 자석이 전기를 만들어 도시를 가동한다는 설명은 하지 않는다.

### 보고서와 엔딩

보고서는 다섯 대표 발견 그림과 내 발명품을 보여 준다. 각 그림의 기본 설명은 한 문장이고 세부 시험은 눌러서 펼친다. 모든 기록을 읽거나 페이지를 넘겨야 최종 미션에 들어가는 조건은 없다.

엔딩은 내가 고친 장치가 사용되는 장면을 보여 주며 긴 요약 글을 다시 읽히지 않는다. 건너뛰기·다시 보기·인증서를 제공한다. 인증서는 실제 완료한 기본 활동을 표시하고 선택 탐구를 하지 않은 학생에게 부족한 성취처럼 표시하지 않는다.

## 6. 내 실험 기록과 자동 비교

기록은 성공 문장 목록이 아니라 학생이 만든 실제 조건과 결과 그림이다. 첫 예상은 바뀌어도 원본을 남긴다.

- 기본 기록: 처음 예상 → 해 본 모습 → 실제 결과.
- 수정이 있으면: 바꾼 부품만 강조한 전후 그림.
- 비교는 앱이 같은 시험·초기 조건인 두 기록을 자동 선택한다.
- 전체 기록 고르기·삭제·고정은 기본 학생 흐름에 넣지 않는다.
- 기록 서랍은 읽기 전용 재생이다. 열람으로 완료나 보상이 추가되지 않는다.
- 기록 그림은 데이터로 생성한다. 실험마다 대용량 이미지·영상 파일을 저장하지 않는다.
- 단원 설명을 할 때는 학생의 기록을 먼저 보여 준다. 정답 문장을 미리 보여 주고 따라 읽게 하지 않는다.
- 두 사람이 한 기기를 쓰면 예상/조작 역할을 바꾸고 결과를 서로 설명한다. 실명·음성 녹음·성향 점수는 저장하지 않는다.

## 7. 모형과 과학 표현

- 이번 모형은 초등 수준의 정성적 탐구용이다. 화면 좌표나 반응 강도를 실제 거리·자기력 단위로 환산하지 않는다.
- 같은 조건에서는 같은 결과가 나온다. 물체는 순간이동하지 않고 허용된 방향으로 이동한다.
- 자기력 반응은 재료·마주 보는 극·거리로 결정한다. 미션 정답 여부가 물리 반응을 바꾸면 안 된다.
- 가까워질수록 반응이 뚜렷해지는 상대적 곡선과 결합/분리 기준을 분리한다. 경계에서 상태가 반복 떨리지 않도록 여유 구간을 둔다.
- 자유 탐색과 비교 시험은 같은 규칙을 쓴다. 비교 시험은 초기 조건과 입력 경로만 고정한다.
- 종이 실험은 지정한 얇은 종이 한 장에 대한 관찰이다. 모든 장벽·두께에 대해 같은 결론을 일반화하지 않는다.
- 반응은 프레임 간 경과 시간으로 계산하고 과도한 시간 차이를 제한한다. 입력 이벤트 횟수가 힘이나 이동량이 되지 않게 한다.
- “힘 관찰 렌즈”는 마주 보는 면·이동 방향·전후 위치를 확대하는 도구다. 자기장·자력선·정확한 힘 수치를 표시하지 않는다.

추가 모듈 후보는 `src/experiment-model.ts`(정성 반응), `src/trial-records.ts`(실험 스냅샷·비교·재생), `src/final-mission.ts`(연결 장치)다. 이름은 구현 시 기존 코드와 조정할 수 있다.

### 상태 분리

1. **실시간 상태:** 드래그 좌표, 속도, 결합 여부, 임시 피드백. 프레임마다 저장하지 않는다.
2. **시험 기록:** 시작 조건, 입력 경로, 결과, 설계 버전. 기록 시 확정한다.
3. **학습 증거:** 어떤 관찰·비교·적용 기록이 완료 조건을 충족하는가.
4. **진행 상태:** 완료 활동, 증거 5개, 최종 완료. 실험 중간 애니메이션과 분리한다.

### 데이터 계약 초안

```ts
type Trial = {
  id: string;
  activity: number;
  kind: string;
  modelVersion: number;
  conditions: Record<string, string | number | boolean>;
  initialObjects: { id: string; x: number; y: number; pole?: 'N' | 'S' }[];
  input: { t: number; objectId: string; x: number; y: number; action?: string }[];
  checkpoints: { t: number; objects: { id: string; x: number; y: number }[];
    event: string }[];
  outcome: string;
  designId?: string;
  designRevision?: number;
};

type LearningEvidence = {
  observedTrialIds: string[];
  comparisons: { left: string; right: string; variable: string; valid: boolean }[];
  transfer: { taskId: string; trialIds: string[]; passed: boolean }[];
  explanations: { standard: string; trialIds: string[]; choice?: string; discussed: boolean }[];
};

type FinalRoute = {
  cargoId: string;
  checkpoint: 'sort' | 'delivery' | 'rings' | 'invention' | 'done';
  segmentTrialIds: Partial<Record<'sort' | 'delivery' | 'rings' | 'invention', string>>;
  mode: 'basic' | 'challenge';
  activeRepair: 'delivery' | 'rings' | 'invention';
  replayEvidenceIds: string[]; // 이미 학습한 구간의 재생 참조, 새로운 성공 시험으로 세지 않음
  selectedDesignId: string;
  selectedDesignRevision: number;
};
```

비교의 `valid`와 적용의 `passed`는 불러올 때에도 실제 기록으로 재검증한다. 저장된 true 값만으로 통과시키지 않는다.

### 기록 크기와 저장 정책

- 이동 경로는 일정 간격으로 샘플링하고 중복점을 줄인다. 기록 한 건은 최대 240개 입력점, 64KB 이내를 초기 예산으로 삼는다.
- 활동당 일반 기록은 최근 12개를 기본 보관하고, 최초 예상·완료 증거·사용자가 비교 대상으로 고정한 기록은 별도 보존한다. 참조 중인 기록은 자동 삭제하지 않는다.
- 예산 초과 시 기록 정밀도를 낮추거나 새 상세 재생 저장을 보류하고 안내한다. 현재 학습 진행과 완료 증거를 버리지 않는다.
- 기록과 이를 참조하는 증거는 같은 IndexedDB 트랜잭션에서 저장한다. 중복 완료·보상 지급은 ID로 방지한다.
- 포인터를 놓거나 비교 시험이 끝난 시점, 구간 완료 시점에 저장한다. 화면을 벗어나면 마지막 유효 상태를 확정한다.
- 재생은 읽기 전용이다. 재생을 보는 행위가 새로운 실험·완료·보상을 만들지 않는다.
- 모형 버전이 달라지면 과거 기록을 새로운 모형으로 임의 계산하지 않는다. 저장된 체크포인트로 과거 결과를 보여 주고 새 실험은 현재 버전으로 기록한다.

### 기존 저장과의 호환

현재 Save.version=1과 IndexedDB 구조를 확인한 뒤 명시적인 v1→v2 변환을 추가한다. 기존 저장을 먼저 백업하고 변환 검증이 끝나기 전에는 원본을 지우지 않는다.

- 이미 완료한 활동·증거·도시 복구·인증서는 유지한다. 새 적용 문제를 풀어야 기존 수료를 되찾는 구조로 바꾸지 않는다.
- 과거 문장 기록을 새 실험 경로나 적용 성공 증거로 꾸며내지 않는다. “이전 활동 기록”으로 읽을 수 있게 유지한다.
- 진행 중 활동은 가능한 조건·배치를 이관하고 새 완료 계약에 필요한 실험만 안내한다. 필요한 데이터가 없으면 해당 실험의 시작 상태로 복원하며 이유를 알린다.
- 기존 최종 완료는 보존하고, 신규 연결 미션은 다시 탐구로 체험할 수 있게 한다.
- 기존 미완료 최종 미션은 기본 모드의 고장 구간부터 시작한다. 앞선 다섯 구역 기록과 유효한 발명 설계를 사용하고 나머지 구간은 이미 검증된 기록으로 재생한다.
- 관리자 미리보기와 재탐구는 본 진행과 저장을 분리한다.
- 저장 실패 시 메모리의 현재 진행을 유지하고 재시도 안내를 제공한다.

### 초기 요청 계획

아래는 **개편 후 목표 목록과 예산**이며 현재 배포 측정값이 아니다. 빌드 해시 파일 수와 실제 전송량은 구현 단계에서 측정해 확정한다.

| 시점 | 필수 요청 목록 | 목표 요청 수 | 목표 전송량 |
|---|---|---|---|
| 첫 화면 | HTML 1, 앱 JS 1, CSS 1, 로고 1, 대표 배경 1, 캐릭터 시트 2 | 7건, 번들 분할 시 최대 10건 | 압축 전송 합계 1.5MB 이내 |

| 첫 활동 진입 | 필요 시 활동 코드 1, 장치 시트 1, 배경 1 | 추가 3건 이내 | 추가 700KB 이내 |

| 음향 | 첫 사용자 조작 후 선택 로드 또는 합성 | 필수 요청에서 제외 | 실패해도 진행 가능 |

현재 도시 청크 용량 경고가 있으므로 파일 크기와 실제 전송량을 구분해 기록한다. 예산을 넘으면 재사용·지연 로드·이미지 압축을 먼저 적용한다.

필수 파일 실패는 파일명·단계·재시도 버튼을 표시하고, 선택 자산 실패는 대체 표시로 진행한다. 동일 파일 요청은 합치고 제한된 재시도를 사용한다. 학교망 30기기 동시 최초 접속은 첫 화면부터 첫 활동까지 별도 검증한다.

## 11. 검증과 수용 기준

### 학생 눈높이

- 첫 화면에서 현재 질문·잡을 물체·다음 행동을 찾아낼 수 있다.
- 동일한 지시가 제목·카드·하단에 반복되지 않는다.
- 학생용 설명·기록은 16px 이상, 행동과 버튼은 18px 이상이다.
- 시험 전에는 결과를 단정하지 않는다. 반응 뒤에만 결과를 표시한다.
- 거리 잠금·기록 선택·증거 연결을 학생이 별도 절차로 배우지 않는다.
- 움직인 부품·그림·비교 문장이 일치한다.
- 초기에 성공한 학생도 재설계 없이 기본 완료한다.
- 학습 결과 표현은 구역마다 한 번, 자신의 관찰과 연결한다.
- 보고서의 모든 문장을 읽는 행위를 완료 조건으로 쓰지 않는다.

### 입력·화면

- 1280×800·1280×720·1024×768에서 질문·실험대·현재 안내·필수 버튼이 동시에 보인다.
- 1024에서 기록은 닫힌 서랍으로 시작한다. 열 때 실험 입력을 멈추고 닫을 때 포커스를 복원한다.
- 터치·마우스·키보드·선택 배치로 같은 상태에 도달한다.
- pointercancel·회전·창 비활성화·두 번째 손가락이 상태를 깨뜨리지 않는다.
- 손가락이 대상을 가려도 반응을 옆에서 볼 수 있다.
- 음소거·움직임 줄이기로도 학습 결과가 유지된다.

### 과학·완료·저장

- 자석이 철을 밀어낸다고 표현하지 않는다. 수레 부착 자석과 화물은 구별한다.
- 종이 비교는 같은 초기 거리·재료·자석을 사용한다.
- 과학 반응이 미션 정답 여부에 따라 숨겨지지 않는다.
- 설계 버전 변경 시 현재 버전에서 시험한다.
- 기본 최종 미션은 고장 구간의 직접 해결과 나머지 구간의 과거 증거 참조를 구분한다.
- 선택 도전·나침반 탐구는 기본 완료를 막지 않으며, 단원 전체 수업의 나침반 관찰은 교사 계획에 명시한다.
- v1 저장의 중간 진행·기존 수료와 최초 증거를 보존한다.
- 기존 테스트 23개를 기준선으로 두고 새 학습 판정·비교·호환 테스트를 추가한다.

### 실제 학생 검증

3~5명의 학생으로 첫 조작 찾기, 별도 설명 없이 진행하기, 자신의 결과 말하기를 먼저 관찰한다. 인원과 관찰 시간은 파일럿 계획이며 이미 수행한 결과가 아니다. 학생이 읽기 전에 물체를 찾는지, 어디에서 멈추는지, 같은 질문을 반복해서 묻는지 기록한다. 자동 검사와 성인 검토를 학생 사용성 검증으로 대체하지 않는다.

## 12. 수정된 화면 시안

[태블릿 화면 시안](tablet-experience-preview.html)은 거리·종이, 발명 설계와 비교, 최종 한 구간 복구, 선택 나침반 탐구를 직접 조작해 보는 독립 웹 시안이다. 같은 폴더의 tablet-preview.css와 tablet-preview.js를 사용한다. 상단의 화면 선택은 검토용 도구이며 실제 학생용 활동 메뉴가 아니다.

시안은 실제 앱의 저장·수료와 연결하지 않는다. 별도 서버·외부 라이브러리 요청 없이 동작하며 조작·기록은 현재 시안 실행 중에만 유지한다. 정성적인 반응과 입력·화면 계약을 검토하는 용도이며 완성된 물리 모형·정식 교육 평가가 아니다.

대표 화면 외의 1~10 활동·메인·도시·보고서·엔딩은 이 문서의 전체 화면 계약에 따라 앱에 구현한다. 화면 시안의 검토 기록은 아래에 실제 확인한 범위만 추가한다.

### 이번 시안에 구현한 범위

- 거리: 자석 직접 이동, 가까워질 때 클립 반응, 먼/가까운 관찰 자동 기록, 방향키와 버튼 대안.
- 종이: 가까운 관찰의 자석 위치 복원, 종이 직접 배치, 같은 시작 조건의 두 결과 자동 비교. 기존 관찰을 비교 기준으로 재사용한다.
- 발명: 뚜껑에 부착된 자석 이동, 몸통의 철판 고정, 동일한 흔들기 시험, 실패/성공, 실제 배치로 그린 비교, 첫 성공 뒤 기본 완료.
- 마지막 복구: 수레 부착 자석과 철 화물 구별, 극 뒤집기, 밀림/끌림, 한 구간 완료. 다른 세 구간은 재생 예시 라벨과 전체 연결 요약으로 표시한다. 실제 과거 경로 재생과 전 구간 선택 도전은 앱 구현 범위로 남긴다.
- 선택 나침반: 자석 위치·극에 따른 바늘 회전. 정성 모형으로 표현하며 정확한 계측 용도가 아니다.
- 기록: 조작 시 자동 생성, 필요할 때 서랍 열기, 그림 중심 비교. 다시 해 보기는 현재 배치를 초기화하고 이미 남긴 기록은 유지한다. 페이지 새로고침 때만 시안 메모리 기록이 초기화된다.

| 1280×800 / 1280×720 / 1024×768 × 대표 4화면 | 가로·세로 문서 넘침 없음, 질문·실험대·하단 필수 버튼 표시 |
| 활성 조작 버튼 크기 | 검사한 12개 화면 상태에서 모두 48×48 CSS px 이상 |
| 직접 조작 | 자석 이동·종이 삽입·발명 자석 배치·수레 배송 확인 |
| 학습 흐름 | 먼/가까운 기록과 종이 자동 비교, 발명 첫 성공 후 설명과 완료, 수레 한 구간 복구 확인 |
| 대체 입력·서랍 | 방향키 이동, 이동 버튼, Escape 닫기 및 원래 기록 버튼으로 포커스 복귀 확인 |
| 나침반 | 위치 변경과 극 뒤집기에 따라 바늘 방향 변경 확인 |
| 코드 | 시안 JS 문법 검사 통과, 확인 시 브라우저 콘솔 오류 없음 |
| 기존 앱 빌드 | TypeScript 및 Vite 빌드 통과. 기존 도시/Phaser 청크 용량 경고 유지 |

브라우저의 화면 크기 변경과 마우스/키보드 검사 결과다. 실물 태블릿의 손가락 입력·회전·멀티터치, 저사양 성능, 학생 사용성, 교실 동시 접속은 이번에 검증하지 않았다. 10개 활동 전체의 앱 개편과 학습 판정·저장 통합 완료를 의미하지 않는다.
